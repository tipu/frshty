Plan a browser task before you run the first command. Collapse first, then count, then route. Collapse: two or more steps in a row whose URL, element text and expected value you already know become one `run-code` probe, run in one shell turn. Use the prelude and the rules in `~/.claude/skills/playwright-cli/references/collapsing.md`; never pick an element with `.first()`, never widen a check, and never treat a vanished loader as success. Count the turns that remain after collapsing. Three or more remaining turns go to the `browser-verifier` subagent in one Agent call, with the exact element text and the exact expected value written out first. One or two remaining turns run inline. Frontend verification on aimyable and nectar is usually deterministic end to end, so it is usually one probe.

If a tool call inside a subagent returns "requires approval" or any permission denial, return that error to the parent immediately. Do NOT invoke `fewer-permission-prompts` or any other skill to "fix" permissions from inside a subagent — scanning transcripts and rewriting settings is way out of scope and produces large retry-heavy logs.
